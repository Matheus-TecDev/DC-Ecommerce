# Digital Store API

REST API of the Digital Store project: Node.js, Express, JWT authentication and JSON file
persistence. Setup, environment variables and limitations are described in the
[main README](../README.md).

```bash
npm start     # node ./bin/www
npm run dev   # restarts on file changes
npm test      # node:test + Supertest
```

## Conventions

- Requests and responses are JSON. Errors are always `{ "erro": "message" }`.
- Authenticated routes expect `Authorization: Bearer <token>` (the legacy `x-access-token` header is
  also accepted).
- Status codes: `400` malformed request, `401` missing or invalid token / wrong credentials,
  `403` not allowed, `404` not found, `409` conflict, `422` validation error.

## Endpoints

### Health

| Method | Route | Auth | Description |
| --- | --- | --- | --- |
| GET | `/` | — | Service status |

### Authentication — `/userauth`

| Method | Route | Auth | Description |
| --- | --- | --- | --- |
| POST | `/userauth/signup` | — | Creates an account. Body: `user` (2–80 chars), `email`, `password` (8–72 chars). Returns `201` with the user, without the password. New accounts always get the `customer` role. |
| POST | `/userauth/login` | — | Body: `email`, `password`. Returns `{ auth, token, user }`. Wrong e-mail and wrong password give the same `401`. |
| GET | `/userauth/me` | token | Returns the user that owns the token |

### Products — `/produtos`

| Method | Route | Auth | Description |
| --- | --- | --- | --- |
| GET | `/produtos` | — | Lists all products |
| GET | `/produtos/:id` | — | One product |
| GET | `/produtos/search?palavra_chave=&info=` | — | Case-insensitive search. `palavra_chave` is `categoria`, `titulo` or `descricao` |
| POST | `/produtos` | admin | Creates a product. All fields required |
| PUT / PATCH | `/produtos/:id` | admin | Updates the fields that were sent |
| DELETE | `/produtos/:id` | admin | Removes a product |

Product fields: `categoria`, `titulo`, `descricao` (text), `valor` (number ≥ 0), `desconto`
(percentage, 0–100) and `img` (an `http(s)` URL or a path under `/imagens`). The `id` is generated by
the API. Unknown fields are ignored.

Demo product images are served from `/imagens`.

### Cart — `/carrinho`

Each user has a single cart, identified by the token. All routes return the detailed cart.

| Method | Route | Auth | Description |
| --- | --- | --- | --- |
| GET | `/carrinho` | token | The user's cart |
| POST | `/carrinho/itens` | token | Adds a product. Body: `produto_id`, optional `quantidade` (1–99, default 1). Adds to the quantity if the product is already in the cart |
| PATCH | `/carrinho/itens/:produtoId` | token | Sets the quantity. Body: `quantidade` |
| DELETE | `/carrinho/itens/:produtoId` | token | Removes an item |
| DELETE | `/carrinho` | token | Empties the cart |

```json
{
  "itens": [
    {
      "produto_id": "2",
      "titulo": "Tênis Sprint Pro",
      "categoria": "Corrida",
      "img": "/imagens/tenis-corrida.png",
      "quantidade": 2,
      "valor": 349.9,
      "desconto": 15,
      "valorUnitario": 297.42,
      "subtotal": 594.84
    }
  ],
  "quantidadeItens": 2,
  "valorBruto": 699.8,
  "descontoCarrinho": 0,
  "descontoTotal": 104.96,
  "valorTotal": 594.84
}
```

(`descricao` omitted above for brevity.) `valorUnitario` is the price after the product discount;
`descontoCarrinho` is an extra percentage stored on the cart (always `0` for carts created by the API).

### Users — `/users`

Accounts are created through `/userauth/signup`. Passwords are never returned.

| Method | Route | Auth | Description |
| --- | --- | --- | --- |
| GET | `/users` | admin | Lists users |
| GET | `/users/:id` | owner or admin | One user |
| PUT / PATCH | `/users/:id` | owner or admin | Updates `user`, `email` and/or `password`. `id` and `role` cannot be changed |
| DELETE | `/users/:id` | owner or admin | Removes the account and its cart |

## Changes from the original API

- `POST /users` and the plain-text `users.json` store were removed; `/userauth/signup` is the only way
  to create an account.
- `/carrinho` used to expose every cart by id without authentication; it is now scoped to the
  authenticated user, and `GET /carrinho/:id/valortotal` became part of `GET /carrinho`.
- `GET /userauth/teste` was renamed to `GET /userauth/me`.
- Not-found and validation cases now return proper status codes instead of `200` with a text message.
- The default port changed from `3000` to `3001`, so it no longer collides with the frontend.

## Data

`data/seed/*.json` holds fictional demo data. On first use each file is copied to `data/`, which is
git-ignored and holds the runtime state. `DATA_DIR` can point the store somewhere else (the tests use
a temporary directory).
